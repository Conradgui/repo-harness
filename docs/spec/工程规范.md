# 工程规范

这份文档是**规范性**的：它约束怎么写、怎么改、怎么验收。与之配套的是 [决策记录](../decisions/README.md)（为什么这么定）和 [后续路线图](../delivery/04-后续路线图.md)（接下来做什么）。

---

## 一、质量门禁

任何改动落地前必须全部通过：

```bash
uv run ruff check .        # 预期 All checks passed
uv run pytest tests/ -q    # 预期全绿
```

两条都是硬门禁。**不允许提交让任一条变红的改动**，也不允许用 `# noqa` 或 `pytest.mark.skip` 绕过而不写明理由。

### lint 规则集

规则在 `pyproject.toml` 的 `[tool.ruff.lint]` 显式声明，每个族有选取理由。**不要用前缀扩大范围**（例如把 `E4,E7,E9` 改成 `E`，那会引入 E501 行长检查，与本项目的取舍不符）。

新增规则族按这个顺序判断：

1. 它能抓住什么真实缺陷？说得出具体场景才加
2. 现有代码违反多少处？先看数量再决定是修还是不加
3. 加进去之后，它会阻止哪类合理写法？

ruff 版本锁在 `>=0.16.0,<0.17.0`。升级时先跑一遍看新规则引入多少问题，再决定是修还是显式 ignore。

## 二、测试规范

完整理由见 [ADR-003](../decisions/003-测试只测行为.md)。规范条款：

### 必须

- **测行为**。断言函数的输入输出、状态变化、错误码
- **新测试要验证它能抓住目标缺陷**。撤销源码修复，确认测试变红，再恢复：

  ```bash
  git stash push <改动的源文件>
  uv run pytest <新测试> -q      # 必须有失败
  git stash pop
  ```

- **离线可跑**。不依赖真实 API key、不依赖网络。provider 交互用 `FakeModelClient` 或本地 HTTP mock

### 禁止

- **断言文件行数**。代码变短不是缺陷
- **断言文档措辞**。改写句子不是缺陷；链接失效才是
- **断言方法定义在哪个文件**。这会锁死重构
- **写会 skip 的测试**。依赖外部程序时改为断言传给它的 argv：

  ```python
  # 不要：装了 rg 才测，没装就 skip
  # 要：monkeypatch subprocess.run，断言 argv
  assert "--" in captured_argv
  assert captured_argv.index("--files") > captured_argv.index("--")
  ```

### 测试分层

| 层 | 判据 | 典型文件 |
|---|---|---|
| L1 契约 | 不启动完整 agent，只验单模块行为 | `test_search_tool.py`、`test_identifiers.py` |
| L2 集成 | 多模块协作，`FakeModelClient` 注入脚本化输出 | `test_engine_acceptance.py` |
| L3 端到端 | 启动真实 CLI 子进程 + 本地 mock provider | `test_provider_config_acceptance.py` |

新工具至少需要 L1 覆盖。

## 三、安全边界规范

完整理由见 [ADR-002](../decisions/002-安全边界用开关而非删除实现.md)。

### 权限决策集中在一处

所有**权限性**判断必须经 `PermissionChecker.check()` 求值。**不允许在工具实现里自行判断能不能做**——那会让"能不能做"散落到十几个文件，且互相矛盾时无人察觉。

`sandbox` 的 `read_only` 模式曾经是例外——它在 `SandboxRunner` 里直接抛 `RuntimeError`，绕过权限层。现已收敛：`PermissionChecker` 先判定并返回 `sandbox_read_only`，工具状态是 `rejected`（策略决策）而不是 `error`（故障）。

`SandboxRunner` 保留自己的 raise，服务于绕过权限层的直接调用（测试会这样调）。真正的硬失败——模式不支持、后端不可用——仍然抛异常，因为它们是配置错误和环境故障，不是策略判断。

求值顺序（先命中先返回）：

```text
profile 裁剪 → plan mode → sandbox read_only（仅 run_shell）→ write_scope → read_only → approval_policy
```

### 收紧靠判断，不靠删除

引入任何限制时的检验方式：**关掉它需要改配置，还是需要重写代码？** 后者说明方案不对。

### 拒绝不中断流程

权限拒绝返回错误码给模型作为下一轮输入，不抛异常终止。模型据此换方法，用户看到的是 agent 调整策略而不是崩溃。

### 模型提供的参数是不可信输入

工具参数由模型生成，必须按不可信处理。已知的一类攻击面：

```python
# 缺 -- 终止符时，模型传入 "--files" 会让 rg 去列文件名而不是搜索
["rg", "-n", "--fixed-strings", "--", pattern, str(path)]
```

新增会把参数传给外部程序的工具时，必须检查参数注入。

## 四、代码规范

### 子进程调用

```python
subprocess.run(
    argv,
    capture_output=True,
    text=True,
    encoding="utf-8",     # 必须显式指定
    errors="replace",     # 必须，防止读取线程崩溃
    check=False,          # 显式写出，即使是默认值
)
```

缺 `encoding=` 时 Python 用系统 locale 解码，非 UTF-8 主机（中文 Windows 是 GBK）上读取线程会抛 `UnicodeDecodeError`，而**该异常不传播**——它只是让 `stdout` 变成 `None`，调用方在很远的地方才报错。

### 标识符时间戳

session / task / run 的 id 必须走 `workspace.id_timestamp()`（UTC）。不要直接用 `datetime.now()`——本地时间不单调，DST 回拨会让 id 排序颠倒，且与 `created_at` 的 UTC 基准不一致。

### 单文件规模

超过 800 行考虑拆分，超过 1200 行必须给出不拆的理由。`RepoHarness` 是历史遗留的反例，拆解方案在路线图 P1。

**注意**：不存在"最小行数"要求。代码变短是好事——项目里曾有一个强制最小行数的测试，已删除。

## 五、文档规范

### 四类文档各司其职

| 类型 | 位置 | 回答的问题 |
|---|---|---|
| 引导性 | `README.md`、`docs/getting-started.md` | 怎么用 |
| 规范性 | `docs/spec/` | 怎么写、怎么改 |
| 计划性 | `docs/delivery/04-后续路线图.md` | 接下来做什么 |
| 决策性 | `docs/decisions/` | 为什么这么定 |

### 数字必须可复现

完整理由见 [ADR-006](../decisions/006-交付数字必须可复现.md)。

文档里的量化指标由脚本产出：

```bash
python scripts/measure.py origin/main    # before 基线
python scripts/measure.py                # 当前
python scripts/permission_probe.py       # 写入权限矩阵
```

写下任何数字前先问：**如果现在要求当场复算，我跑哪条命令？** 答不上来就不要写。

**会过期的数字不写进文档**——提交数在下一次提交时就错了，写命令而不是数值。

### 什么时候写 ADR

判据：**如果六个月后有人问"为什么当初不那样做"，而答案不在代码里，就该有一条 ADR。**

不为例行实现选择写 ADR。要写的是放弃某条路线、引入长期约束、或推翻先前决策这类。

## 六、Stage gate

每个阶段收尾前，由 `.claude/agents/stage-gate.md` 定义的审核 agent 独立复核。它会重跑每个数字背后的命令，检查改动与 commit message 是否一致，以及路线图是否诚实。

**不要自评。** 这个项目已经证明自评会漏掉整类问题——前两次 gate 分别报出 14 项和 9 项发现，其中包括一份刚写下"数字必须可复现"的文档里手写的九个数字。

## 七、迭代纪律

三条来自一次技术债治理的复盘。那次迭代的收尾方式是：

```text
写计划文档 → 实现 → 发现风险 → 删掉实现加 gate → 写文档说明 gate → 加测试断言文档写了 gate
```

每轮都"完成了任务"，但产出是限制而不是能力。规矩：

1. **安全边界用开关，不删实现**（[ADR-002](../decisions/002-安全边界用开关而非删除实现.md)）
2. **每轮以能跑通的功能收尾，不以新增的文档收尾**。一轮下来只多了文档和 gate，这轮是负产出
3. **测试只测行为**（[ADR-003](../decisions/003-测试只测行为.md)）

重构时额外一条：**一次一步，每步跑全量测试并单独提交。** 中途失败时才能二分定位。`MemoryCoordinator` 的提取分了两个提交，第二步的机械迁移一次就引入了两类错误（漏了模块级常量、丢了 keyword-only 参数），是全量测试抓住的。
