# 问题归因记录

## 文档说明

这份文档用于记录项目维护过程中遇到的问题归因。它帮助维护者区分“环境触发条件”和“代码库根因”，也方便未来维护者判断类似问题是否属于可移植性、依赖声明、测试资产或工程约束问题。

本文不是对外申诉材料，也不是一次性故障复盘。每次重要问题排查都应按日期追加记录，保留当时的判断口径和证据。

## 更新规则

- 每次问题排查新增一个日期小节，标题格式为 `YYYY-MM-DD：问题主题`。
- 每条记录至少包含总结结论、分类表、维护者判断口径和后续注意。
- 如果后续证据推翻了旧判断，应追加“修正说明”，不要直接删除旧记录。
- 记录中可以保留当时的项目名、路径和命令；这些属于历史上下文。

### 2026-05-03：Windows 适配问题归因

#### 总结结论

这批失败并不是“只是这台电脑有问题”。更准确地说，是本地 Windows 环境把仓库中原本就存在的跨平台假设、可移植性缺口和工程约束不严谨的问题暴露出来了。

#### 分类表

| 失败点 | 是否由本地环境触发 | 是否属于代码库需要处理的问题 | 为什么重要 |
| --- | --- | --- | --- |
| `ZoneInfo("Asia/Shanghai")` 在缺少 `tzdata` 时失败 | 是 | 是 | 项目依赖时区数据，却没有显式声明依赖。 |
| benchmark 的可复现性元数据受宿主机 locale 影响 | 是 | 是 | 可复现性输出不应随着运行机器的区域设置静默漂移。 |
| verifier 命令写死为 `python3 -c ...` | 是 | 是 | benchmark 假设存在 `python3` 命令，但这在 Windows 上并不可靠。 |
| Windows shell 启动所需变量被过滤掉 | 是 | 是 | 运行时的安全过滤误删了 shell 自身启动需要的环境变量。 |
| 带 POSIX 语法的 shell 命令在平台默认 shell 下执行 | 是 | 是 | 测试和命令内容默认采用 POSIX 语义，但 runtime 没有保证使用兼容 shell。 |
| 缺少 `docs/review-pack/README.md` | 否 | 是 | 测试要求存在的仓库资产缺失。 |
| 缺少 `docs/architecture/agent-harness-v1-overview.md` | 否 | 是 | 测试要求存在的仓库资产缺失。 |

#### 维护者判断口径

后续整理 issue、commit message、release note 或简历项目材料时，建议统一使用这些表述：

- “跨平台兼容性加固”
- “benchmark 可移植性修复”
- “Windows 运行时兼容性修复”
- “可复现性元数据稳定化”
- “维护者文档与测试资产补齐”

不建议把这些问题描述成一次性的本机怪异现象。机器只是复现环境，不是根因本身。

#### 后续注意

- Windows 适配不应演变成单独的 Windows 分支；当前目标仍然是统一代码路径下的跨平台可用。
- 修复可移植性问题时，优先把平台差异收敛到清晰边界，例如 shell 选择、环境变量 allowlist、路径处理和 verifier 执行。
- 文档需要同时服务维护者自己和未来协作者：记录足够具体的根因、文件位置和验证命令，但避免写成临时聊天记录。
- 后续遇到类似问题时，优先检查项目是否隐含了平台、locale、shell、路径或本地状态假设。
