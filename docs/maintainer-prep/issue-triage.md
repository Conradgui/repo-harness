# 问题归因

## 总结结论

这批失败并不是“只是这台电脑有问题”。更准确地说，是本地 Windows 环境把仓库中原本就存在的跨平台假设、可移植性缺口和工程约束不严谨的问题暴露出来了。

## 分类表

| 失败点 | 是否由本地环境触发 | 是否属于代码库问题 | 为什么重要 |
| --- | --- | --- | --- |
| `ZoneInfo("Asia/Shanghai")` 在缺少 `tzdata` 时失败 | 是 | 是 | 项目依赖时区数据，却没有显式声明依赖。 |
| benchmark 的可复现性元数据受宿主机 locale 影响 | 是 | 是 | 可复现性输出不应随着运行机器的区域设置静默漂移。 |
| verifier 命令写死为 `python3 -c ...` | 是 | 是 | benchmark 假设存在 `python3` 命令，但这在 Windows 上并不可靠。 |
| Windows shell 启动所需变量被过滤掉 | 是 | 是 | 运行时的安全过滤误删了 shell 自身启动需要的环境变量。 |
| 带 POSIX 语法的 shell 命令在平台默认 shell 下执行 | 是 | 是 | 测试和命令内容默认采用 POSIX 语义，但 runtime 没有保证使用兼容 shell。 |
| 缺少 `docs/review-pack/README.md` | 否 | 是 | 测试要求存在的仓库资产缺失。 |
| 缺少 `docs/architecture/agent-harness-v1-overview.md` | 否 | 是 | 测试要求存在的仓库资产缺失。 |

## 对维护者的建议表述

建议向上游或项目管理员描述为：

- “跨平台兼容性加固”
- “benchmark 可移植性修复”
- “Windows 运行时兼容性修复”
- “可复现性元数据稳定化”

不建议把这些问题描述成一次性的本机怪异现象。机器只是复现环境，不是根因本身。
