# 问题归因

这份记录用于维护者复盘 Windows 适配过程中暴露的问题。读者包括当前维护者本人和未来可能接手项目的人，因此这里更关注“问题为什么发生、以后如何判断类似问题”，而不是写成对外甩锅或向上游申诉的材料。

版本管理口径：本文件记录的是当前阶段的归因判断。后续如果出现新的平台问题，优先追加新分类或新小节；除非原判断被证伪，不要直接改写旧结论。

## 总结结论

这批失败并不是“只是这台电脑有问题”。更准确地说，是本地 Windows 环境把仓库中原本就存在的跨平台假设、可移植性缺口和工程约束不严谨的问题暴露出来了。

## 维护者判断口径

后续整理 issue、commit message、release note 或简历项目材料时，建议统一使用这些表述：

- “跨平台兼容性加固”
- “benchmark 可移植性修复”
- “Windows 运行时兼容性修复”
- “可复现性元数据稳定化”
- “维护者文档与测试资产补齐”

不建议把这些问题描述成一次性的本机怪异现象。机器只是复现环境，不是根因本身。维护者以后遇到类似问题时，优先检查项目是否隐含了平台、locale、shell、路径或本地状态假设。

## 后续注意事项

- Windows 适配不应演变成单独的 Windows 分支；当前目标仍然是统一代码路径下的跨平台可用。
- 修复可移植性问题时，优先把平台差异收敛到清晰边界，例如 shell 选择、环境变量 allowlist、路径处理和 verifier 执行。
- 文档需要同时服务维护者自己和未来协作者：记录足够具体的根因、文件位置和验证命令，但避免写成临时聊天记录。
