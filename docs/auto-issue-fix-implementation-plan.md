# RepoHarness Auto Issue Fix 实现计划

## 概要

Auto Issue Fix 以 RepoHarness 内置子命令和 REPL 命令落地，同时保留未来拆成 workflow plugin 的边界。当前阶段已经从“框架与安全预演”升级为“真实执行 + dry-run 预演”：非 dry-run 会进入 GitHub issue 获取、隔离 clone、RepoHarness 修复、测试验证、自动审查、commit、push 和 draft PR 创建。

实现继续复用现有 CLI/config/provider/runtime/evidence，不绕过 permission gate、tool policy、sandbox 或 RunStore。默认 GitHub backend 使用 `gh` CLI，不引入 GitHub SDK。

实现原则：Auto Issue Fix 输出候选修复，不替代人的维护责任。默认推荐 `review-gated`；`draft-auto` 只减少中途人工暂停，不能关闭自动审查，也不能跳过人工最终 review。公开 PR body 必须面向维护者，默认不写入工具链、模型、实验记录、trace 或本地 evidence 说明。

## CLI 与 REPL 设计

命令入口：

```bash
repo-harness auto-issue-fix --repo <url|owner/name> --issue <number> --mode draft-auto --test-command "python -m pytest -q"
repo-harness auto-issue-fix --discover --source trending --criteria bug,test --mode draft-auto
repo-harness auto-issue-fix --repo <url|owner/name> --issue <number> --dry-run
```

REPL 入口：

```text
/auto-issue-fix
/auto-issue-fix --repo owner/name --issue 123
/auto-issue-fix --repo owner/name --issue 123 --mode draft-auto
/auto-issue-fix --repo owner/name --issue 123 --dry-run
```

普通 REPL 中不带参数的 `/auto-issue-fix` 会进入引导式流程，依次询问模式、仓库、issue 编号和可选测试命令。默认模式是 `review-gated` 真实执行；用户输入 `dry-run` 才只生成预演证据，输入 `draft-auto` 才进入草稿 PR 自动化模式。仓库留空生成 `--discover --source trending --criteria bug,test`，输入仓库但 issue 留空生成 `--discover --source repo --repo <owner/name> --criteria bug,test`。非交互环境不进入引导，必须显式传入 `--repo` / `--issue` 或 discovery 参数。

关键参数：

- `--mode review-gated|draft-auto`：默认 `review-gated`。
- `--dry-run`：只生成证据计划，不执行 clone、push 或 PR 副作用。
- `--workdir <path>`：覆盖默认隔离 clone 目录。
- `--provider` / `--model` / `--base-url` / `--host`：真实修复 turn 使用的 provider 配置；MiMo 等 `/chat/completions` 后端使用 `--provider chat-completions`。
- `--auto-review required`：自动审查门策略；当前固定为 required。
- `--max-review-repairs <n>`：`needs_fix` 后允许的受限修复回合数，默认 2。
- `--resume <run_id>`：恢复参数，当前写入 checkpoint，后续继续增强恢复能力。
- `--evidence-dir <path>`：覆盖默认 `.repo-harness/auto-issue-fix/<run_id>`。
- `--workspace-root <path>`：Auto Issue Fix 运行和证据生成的工作区根目录。
- `--test-command <command>`：验证命令；未指定时按仓库配置推断。
- `--include-local-paths`：显式允许报告中保留本地绝对路径。

## 模块边界

`repo_harness.auto_issue_fix` 当前负责：

- `AutoIssueFixConfig`：归一化用户输入、任务来源、模式、自动审查策略、provider 和恢复参数。
- `GhCliBackend`：通过 `gh` CLI 获取 issue、搜索候选、clone、fork 和创建 draft PR。
- `AutoIssueFixReviewGate`：记录每个审查阶段的 verdict、摘要、修复要求和尝试次数。
- `AutoIssueFixRunRecord`：模板和 JSON 使用的可移植运行状态。
- live runner：issue 选择、workspace 准备、RepoHarness 修复 turn、测试、diff gate、commit、push、draft PR。
- 证据渲染：`run-record.md`、`run-record.json`、`pr-body.md`、`formal-report-summary.md`、`pr-ready-fallback.md`。
- 真实日志：`issue.json`、`baseline-repro.log`、`fix-run.log`、`test-after-fix.log`、`git-diff.patch`、`pr-url.txt`。
- 自动审查工件：`reviews/review-<stage>.json`、`reviews/review-<stage>.md`、`decision-log.jsonl`、`checkpoint.json`。

## 自动审查门设计

所有模式共享自动审查门：

- `review-gated`：自动审查通过后，commit、push、PR 前仍由人确认；非 TTY 环境写 checkpoint 后暂停。
- `draft-auto`：自动审查通过后不要求人类中途暂停；任何 `block` 都必须停止。

审查阶段固定为 task、plan、context、diff、tests、security、pr-readiness。verdict 固定为 `pass`、`needs_fix`、`block`。

当前 reviewer 是规则化只读审查：基于 issue、diff、测试结果、secret scan 和 changed paths 判断是否允许进入下一阶段。后续可替换为模型 reviewer，但 reviewer 仍不能写文件或执行修复。

新增维护者信任审查门 `maintainer-trust`：扫描公开 PR title、body、commit message 和 branch，发现 `AI`、`RepoHarness`、`MiMo`、`experiment`、`model`、`trace`、`benchmark`、`dogfood`、`generated by` 等工具实验说明时阻断发布。当前保留既有内部分支前缀，统一改名会在后续命名调整阶段处理。

默认 `pr-body.md` 模板固定为五段式：`Summary`、`Related Issue`、`Validation`、`Scope`、`Notes for Maintainers`。本地 run record 和 formal report 可以保留工具链证据，公开 PR body 只保留 issue、变更范围、验证结果和维护者需要看到的说明。

## GitHub 策略

默认单元测试和 CI 测试使用 fake backend / mocked `gh`，原因是：

- 测试必须确定、快速、可重复。
- 默认测试不能依赖真实 GitHub 账号、网络、rate limit 或权限状态。
- 默认测试不能意外创建真实 fork、分支或 PR。

真实 GitHub 覆盖必须显式 opt-in：

```bash
REPO_HARNESS_AUTO_ISSUE_FIX_LIVE_GITHUB=1
```

live 测试只能使用 sandbox 仓库，必须创建 draft PR，并记录 PR URL 与清理建议。

## 安全行为

live runner 遇到以下任一失败时必须阻断 push / PR：

- 自动审查 verdict 为 `block`。
- `needs_fix` 超过最大受限修复次数。
- test gate 失败。
- diff gate 失败。
- write-scope gate 失败。
- secret scan 失败。
- GitHub authentication 失败。
- branch / fork setup 失败。
- GitHub 返回 blocked、forbidden、permission denied、cannot perform action 等错误。
- 维护者信任审查门发现公开 PR 文案包含工具实验说明或敏感信息。

阻断后写入 fallback 工件，不强行提交 PR。真实 PR 一律 draft，不自动 ready-for-review。

## 测试计划

当前阶段测试覆盖：

- 标准模板文件名，包括 `formal-report-summary.md`。
- 默认路径普适化和 secret redaction。
- dry-run CLI 证据生成。
- REPL `/auto-issue-fix` dry-run 预演。
- REPL `/auto-issue-fix` 无参数引导式流程，覆盖默认 `review-gated`、`dry-run` 和 `draft-auto`。
- `review-gated` 也生成自动审查门。
- `draft-auto` 不能关闭自动审查。
- fake GitHub backend 下的完整 live runner：issue -> clone -> baseline -> RepoHarness scripted fix -> tests -> commit -> fake push -> fake draft PR。
- `review-gated` 非 TTY 在 commit 前暂停并写 checkpoint。
- 无 diff / gate block 时不创建 PR。
- `pr-body.md` 包含五段式维护者模板，并排除工具实验说明。
- `maintainer-trust` 在 `draft-auto` 下命中敏感公开文案时阻断 PR 创建。
- GitHub blocked / forbidden / permission denied 错误分类后不重试、不绕过，只生成 fallback。
- `--max-review-repairs` 参数校验。

后续应继续增强：

- live GitHub opt-in dogfood。
- `--resume <run_id>` 从 checkpoint 恢复真实执行。
- 模型 reviewer 和 `needs_fix` 受限修复回合。
- 更细的 issue discovery 评分和复杂冲突处理。
