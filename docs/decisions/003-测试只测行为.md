# ADR-003 · 测试只测行为，不测形状

**状态**：约束，长期生效
**日期**：2026-07-27

---

## 处境

代码库里有两类测试，它们不保护正确性，只增加改动成本。

**最小行数棘轮** —— `tests/test_architecture_boundaries.py` 整个文件只有一个测试：

```python
minimum_lines = {"repo_harness/core/tool_executor.py": 120, ...}
assert len(lines) >= minimum, f"{relative} still looks like a shim"
```

对 10 个模块强制最小行数。**代码变短就失败。** 这是项目只增不减的直接机制——任何精简都要先和测试套件打架。

**文档散文断言** —— `test_repo_harness.py` 中 11 个函数断言特定句子出现在特定 markdown 文件里：

```python
assert "文档同步是功能完成后的必需门禁" in maintainer_readme
```

改写措辞就失败，而链接指向已删除文件时照样通过。它保护的是文本，不是正确性。

## 决策

**测试断言行为，不断言形状。**

| 不要测 | 因为 | 改测 |
|---|---|---|
| 文件行数 | 阻止一切精简 | 该模块提供的行为 |
| 文档措辞 | 改写即失败，删链接不失败 | 链接可解析、入口存在 |
| 方法定义在哪个文件 | 阻止重构 | 调用产生的效果 |
| 文件是否存在 | 存在不等于正确 | 文件内容被正确使用 |

## 两条补充规则

**1 · 会 skip 的测试等于没测。**

`tests/test_search_tool.py` 第一版在没装 ripgrep 的机器上跑出 `1 passed, 5 skipped`——5 个用例什么都没验证。重写成断言传给 ripgrep 的 argv，不再依赖它是否安装。开发机与 CI 行为一致。

**2 · 新测试必须验证它能抓住目标 bug。**

写完测试后撤销源码修复，确认测试变红：

```bash
git stash push repo_harness/tools/__init__.py
uv run pytest tests/test_search_tool.py -q     # 应有失败
git stash pop
```

没做这一步的测试不可信——它可能因为断言太松而恒真。本次两组新测试都做了这个验证：search 撤销后 4/13 变红，identifiers 撤销后 5/6 变红。

## 替代方案而非净删除

移除 309 行散文断言的同时新增了 `tests/test_docs_integrity.py`：全部内部 markdown 链接可解析、README 指向的指南存在、指南让用户运行的 CLI 入口在打包配置里已声明、没有空 markdown 文件。

前者检查文件"看起来像什么"，后者检查文档集"是否自洽"。

## 一个已知的副作用

`test_docs_integrity.py` 是参数化的，每加一篇 markdown 就多一个用例。因此**测试总数不适合作为交付指标**——它会随文档增长自我膨胀。要衡量覆盖，看具体模块的用例数。
