# ADR-002 · 安全边界用开关表达，不删除实现

**状态**：约束，长期生效
**日期**：2026-07-27

---

## 处境

`codex` 分支为了实现「Phase 0 只读」，把 `tool_write_file` 和 `tool_patch_file` 的函数体删掉，换成一句 `raise`：

```python
def tool_write_file(agent, args):
    del agent, args
    raise FileMutationDisabledError(FILE_MUTATION_DISABLED_MESSAGE)
```

不是注释掉，不是加开关——是删除。同时在另外三层（工具画像、权限检查、auto-issue-fix runner）各加一道拦截。

## 问题

**删掉的能力找不回来，关掉的能力随时能开。**

后果是具体的：

1. 想恢复写入能力，必须重写实现——而 `main` 上还留着完好的版本，这意味着那次删除的净效果是让分支落后于主干
2. 四层拦截散落在四个文件，任何一层没拆干净就依然不能工作
3. 权限层写了完整的 `write_scope` 细粒度校验，但上面一行无条件 deny 让它成了永不可达的死代码——两轮迭代的产物互相矛盾地留在同一个文件里

## 决策

**安全边界必须表达为配置开关或权限判断，实现代码保持完整。**

具体到这个代码库，正确的形态是 `permissions.py` 里已有的分层：

```text
profile 裁剪 → plan mode → write_scope → read_only → approval_policy
```

每一层都是**判断**，不是**删除**。要收紧就调整判断，要放开就改配置。

## 检验方式

引入任何安全限制时问一句：**关掉这个限制需要改配置，还是需要重写代码？** 如果是后者，方案不对。
