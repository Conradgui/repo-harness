# ADR-006 · 交付文档中的数字必须由脚本产出

**状态**：约束，长期生效
**日期**：2026-07-27

---

## 处境

这条约束是被自己的错误逼出来的。交付文档在两轮里出现了同一类问题。

**第一轮**：报告写「lint 错误 199 个，改动前后零新增，实测对比确认」。事实上那次会话里唯一一次运行 ruff 因文件锁失败，**199 是推测后写成结论的**。实测：`origin/main` 是 198，交付分支当时是 171——不是「零新增」而是「净减少 27」。

**第二轮**：修正后又写「源码 17,191 → 12,670，降 26%」。stage-gate 审核发现这两个数字**口径不同、基线也不同**：17,191 是分支第一个提交的物理行数，12,670 是另一个提交的非空行数。一个 raw 减一个非空，跨两个基线。同口径实测降幅当时是约 −15%（当前值见 `scripts/measure.py`），不是 −26%。

同一轮里还有：测试数在三份文档里出现三个不同值；提交数写 8 而实际是 10；「115 个方法」与同文档的 108 自相矛盾；`sandbox` 的测试被列为待办，而它在 `main` 上就已存在。

## 问题的性质

这不是粗心。**手写数字必然漂移**，因为：

- 每次改动都会让上一次写下的数字过期
- 不同时刻用不同方式测量（`wc -l` vs `Measure-Object` vs 排除空行）会得到不同结果，而文档看不出用的哪种
- 「前后对比」的 before 一旦凭记忆填写，就永远无法复算

而**未经验证的数字一旦进了交付文档，就会被当成事实继续传播**——后面的文档会引用它，简历会引用它，面试会讲它。

## 决策

**交付文档中的每个量化指标，都必须能由一条可复现的命令产出。**

落地为 `scripts/measure.py`：

```bash
python scripts/measure.py origin/main   # before
python scripts/measure.py               # after
```

它固定了三件事：

1. **唯一的行数定义**——物理行数（含空行）
2. **唯一的文件范围**——`git ls-files`，因此未跟踪的临时文件永不计入
3. **唯一的 before 基线**——`origin/main`，通过临时 worktree 测量，不触碰工作树

`RepoHarness` 的方法数和类体行数用 AST 取，不用 grep 估。

## 配套：stage gate 审核

`.claude/agents/stage-gate.md` 定义了一个审核 agent，在每个阶段结束时**重新运行每个数字背后的命令**。它的第一条检查项就是：这个数字的来源命令是什么，重跑一遍是多少。

无法重建来源的数字算作发现项，即使它碰巧是对的。

第一次运行这个 gate 就判了 fail，列出 14 项发现——上面提到的问题全是它找出来的。

## 检验方式

写下任何数字前问一句：**如果有人现在要求我当场复算，我跑哪条命令？**

答不上来就不要写。
