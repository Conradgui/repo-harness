2 用户流程梳理

2.1 核心任务流

1
PREFLIGHT 预检
加载工作区、provider 配置、隔离后端状态检查
uv run repo-harness --cwd ./repo
2
DIAGNOSE 诊断
Agent 使用只读工具读取文件、定位问题根因
read tests/test_pricing.py
3
PROPOSE 提议
Agent 生成补丁和验证命令
patch src/pricing.py
4
AUTHORIZE 授权
权限门检查 write_scope / approval_policy
[approve] fs.write
5
EXECUTE + VERIFY
应用补丁、运行测试、验证结果
python -m pytest -q
6
SUMMARY 收尾
生成 task_state / trace / report，记忆候选进 Review Queue
.repo-harness/runs/

2.2 Auto Issue Fix 流（测试命令推断已扩展到 9 种语言）

1
获取 Issue
从 GitHub 读取 issue 或 discovery 筛选
auto-issue-fix --repo owner/name --issue 123
2
隔离 Clone
创建分支、隔离工作区
clone + create branch
3
修复 Turn
调用 RepoHarness runtime 执行修复
run_repoharness_fix_turn()
4
测试验证
自动推断：Python/npm/Go/Rust/Maven/Gradle/.NET/Ruby/CMake
infer_test_commands()
5
审查门
自动审查 + maintainer-trust 门
review-gated / draft-auto
6
Draft PR
commit、push、创建 draft PR，生成证据包
evidence/

repo_harness/sandbox.py:56-66,97-102 · repo_harness/config.py:251-285 · docs/decisions/007-read-only-不再有豁免.md
审查发现若干 sandbox 隔离的 fail-open 回退：① read_only 原先仍咨询命令过滤器豁免（excluded_commands），被 git status/../whoami 等不含 shell 元字符的 git dashed-external 分发绕过，可在 read_only 下执行任意程序（ADR-007）；② 模式名拼错（如 READ_ONLY）曾静默 fall through 到无沙箱执行（sandbox.py:53-56）；③ 为克隆仓库构建 agent 时缺 CLI args，_resolve_sandbox_for_directory 曾回退 SandboxConfig()(mode off)，使声明 read_only 的克隆仓库全程无隔离（config.py:279-285）；④ 仓库自身 .env 的 REPO_HARNESS_SANDBOX=off 可覆盖操作者配置、由不可信内容决定自身隔离级别（config.py:251-259）。
已修复（移除不安全机制）：read_only 先校验模式再 raise RuntimeError("sandbox read_only blocks run_shell")，完全不再咨询命令过滤器（sandbox.py:63-64）；两处 fail-open 回退路径已关闭；.env 决定隔离级别的覆盖已移除。交付文档数字若不可复现则 stage-gate 判 fail（ADR-006）。
保留声明：上述为移除/收紧不安全的 fail-open 机制，不等于 sandbox 已无逃逸可能——Windows 无 bubblewrap 等价物（见 Issue 12），best_effort 下过滤器本就非安全边界（ADR-007）。
